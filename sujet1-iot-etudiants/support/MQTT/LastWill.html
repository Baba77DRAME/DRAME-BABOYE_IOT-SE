Last Will Testament (LWT)

Définition du LWT

Chaque node (ou l'adaptateur MQTT du simulateur pour chaque node simulé) configure un LWT à la connexion au broker.

ParamètreValeur
Topicreptiles/v1/nodes/{zone}/{node-id}/availability
Payload{"v":1,"node":"{node-id}","zone":"{zone}","status":"offline","ts":0}
QoS1
Retaintrue
Délai de publication (willDelayInterval)0 s (publication immédiate à la déconnexion)

Publication de l'état online

Dès la connexion réussie au broker, l'adaptateur MQTT publie sur le même topic :

Topic  : reptiles/v1/nodes/DES/N-DES-01/availability
QoS    : 1
Retain : true
Payload :
{
  "v": 1,
  "node": "N-DES-01",
  "zone": "DES",
  "status": "online",
  "ts": 1700000000000
}

Ce message écrase le LWT offline éventuellement retenu par le broker lors d'une déconnexion précédente.

Comportement lors d'une déconnexion brutale

  1. Le simulateur / node perd la connexion TCP sans envoyer de DISCONNECT.
  2. Le broker Mosquitto détecte l'absence de PINGREQ dans le délai keepAlive (configuré à 60 s).
  3. Le broker publie automatiquement le LWT sur reptiles/v1/nodes/{zone}/{node-id}/availability avec status=offline et retain=true.
  4. Le front web reçoit le message et passe le node en état "offline" dans l'interface.
  5. Le serveur démarre un watchdog : si aucun message n'est reçu depuis ce node pendant 2 × heartbeatPeriod, une alerte node_offline est publiée sur reptiles/v1/alerts/{zone}/{node-id}.

Séquence complète de connexion

Node/adaptateur → Broker   CONNECT (willTopic, willPayload offline, willQoS=1, willRetain=1, keepAlive=60)
Broker → Node              CONNACK
Node/adaptateur → Broker   PUBLISH availability status=online QoS=1 retain=1
Broker → Front             PUBLISH availability status=online (abonnés notifiés)

--- fonctionnement normal ---

--- déconnexion brutale ---
[timeout keepAlive 60 s]
Broker → Front             PUBLISH availability status=offline (LWT, retained)
Serveur                    watchdog déclenché après 2 × heartbeatPeriod sans message

Cas particulier — simulateur multi-nodes

Le simulateur est un processus unique qui émet des messages pour 28 nodes. L'adaptateur MQTT gère 28 connexions logiques (une par node) ou une connexion unique avec LWT de niveau site.

Option retenue : connexion unique avec LWT de niveau site.

ParamètreValeur
Topic LWT sitereptiles/v1/site/availability
Payload{"v":1,"status":"offline","source":"simulator","ts":0}
QoS1
Retaintrue

Si le simulateur s'arrête, tous les nodes simulés sont considérés offline. Le front affiche une bannière "Simulateur déconnecté".
