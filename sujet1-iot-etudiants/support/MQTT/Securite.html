Sécurité — Authentification Mosquitto, ACL, Rôles

Utilisateurs Mosquitto

UtilisateurRôleMot de passeDescription
simulatorSimulateurHashé (bcrypt)L'adaptateur MQTT du simulateur publie tous les messages de tous les nodes simulés
frontendFront webHashé (bcrypt)Tableau de bord — lecture seule sur les données, écriture sur les commandes
serverServeur (watchdog, alerting)Hashé (bcrypt)Publie les alertes, souscrit aux heartbeats pour le watchdog
adminAdministrateurHashé (bcrypt)Accès complet pour maintenance, diagnostic, configuration
node-{node-id}Node réel (hardware)Hashé (bcrypt)Un compte par node physique déployé. Publie uniquement ses propres topics.

Les mots de passe sont générés avec mosquitto_passwd et stockés dans /etc/mosquitto/passwd.

ACL — Access Control List

Rôle : simulator

OpérationTopic patternJustification
writereptiles/v1/nodes/#Publie telemetry, events, heartbeat, availability, ack pour tous les nodes simulés
readreptiles/v1/nodes/+/+/cmdReçoit les commandes destinées aux nodes simulés
writereptiles/v1/site/availabilityLWT de niveau site

Rôle : frontend

OpérationTopic patternJustification
readreptiles/v1/nodes/#Souscrit à toute la télémétrie, événements, heartbeat, availability, ack
readreptiles/v1/alerts/#Affiche les alertes actives
readreptiles/v1/site/#État global du simulateur
writereptiles/v1/nodes/+/+/cmdEnvoie des commandes. Limité au topic cmd uniquement.

Rôle : server

OpérationTopic patternJustification
readreptiles/v1/nodes/#Analyse des mesures pour détection d'alertes et watchdog
writereptiles/v1/alerts/#Publie les alertes générées
writereptiles/v1/nodes/+/+/cmdCommandes automatiques (safety_cut en cas d'urgence)

Rôle : admin

OpérationTopic patternJustification
readwrite#Accès total pour maintenance

Rôle : node-{node-id} (hardware réel)

OpérationTopic patternJustification
writereptiles/v1/nodes/{zone}/{node-id}/telemetryPublie uniquement sa propre télémétrie
writereptiles/v1/nodes/{zone}/{node-id}/eventsPublie uniquement ses propres événements
writereptiles/v1/nodes/{zone}/{node-id}/heartbeatPublie uniquement son heartbeat
writereptiles/v1/nodes/{zone}/{node-id}/availabilityLWT et publication online
writereptiles/v1/nodes/{zone}/{node-id}/ackPublie uniquement ses ACK
readreptiles/v1/nodes/{zone}/{node-id}/cmdReçoit uniquement ses propres commandes

Un node ne peut pas lire les données des autres nodes ni publier sur leurs topics.

Fichier de configuration Mosquitto

Fichier : /etc/mosquitto/mosquitto.conf

listener 1883
listener 9001
protocol websockets

allow_anonymous false
password_file /etc/mosquitto/passwd
acl_file /etc/mosquitto/acl

persistence true
persistence_location /var/lib/mosquitto/

log_dest file /var/log/mosquitto/mosquitto.log
log_type error
log_type warning
log_type notice
log_type information

max_keepalive 120

Fichier ACL Mosquitto

Fichier : /etc/mosquitto/acl

# Administrateur
user admin
topic readwrite #

# Simulateur (adaptateur MQTT)
user simulator
topic write reptiles/v1/nodes/#
topic read reptiles/v1/nodes/+/+/cmd
topic write reptiles/v1/site/availability

# Serveur (watchdog, alerting)
user server
topic read reptiles/v1/nodes/#
topic write reptiles/v1/alerts/#
topic write reptiles/v1/nodes/+/+/cmd

# Front web
user frontend
topic read reptiles/v1/nodes/#
topic read reptiles/v1/alerts/#
topic read reptiles/v1/site/#
topic write reptiles/v1/nodes/+/+/cmd

# Nodes hardware réels (pattern %u = username = node-N-DES-01, etc.)
# Le {zone}/{node-id} est extrait du username dans le code du node.
# Exemple pour node-N-DES-01 connecté avec user node-N-DES-01 :
user node-N-DES-01
topic write reptiles/v1/nodes/DES/N-DES-01/telemetry
topic write reptiles/v1/nodes/DES/N-DES-01/events
topic write reptiles/v1/nodes/DES/N-DES-01/heartbeat
topic write reptiles/v1/nodes/DES/N-DES-01/availability
topic write reptiles/v1/nodes/DES/N-DES-01/ack
topic read  reptiles/v1/nodes/DES/N-DES-01/cmd

Hypothèse : en production avec de nombreux nodes hardware réels, une solution de provisioning automatique (ex: HiveMQ avec RBAC dynamique, ou un plugin Mosquitto) est préférable à la gestion manuelle de chaque entrée ACL. Dans le cadre de ce projet (simulateur), les 4 comptes principaux suffisent.

Transport sécurisé (recommandation)

Dans l'architecture actuelle (réseau local), TLS n'est pas requis. Si le broker est exposé sur internet :

  • Activer TLS sur le port 8883 (MQTT) et 8084 (MQTT over WebSocket).
  • Certificat auto-signé ou Let's Encrypt.
  • Configurer cafile, certfile, keyfile dans mosquitto.conf.
