Commandes et Acquittements

Actions disponibles dans le simulateur : lamp, light, setpoint, safety_cut, interval, reboot, identify.

Cycle commande → traitement → ACK

Front / Serveur
  │
  ├─ génère cmdId unique ("cmd-{date}-{seq}")
  ├─ génère correlationId (lié à la session ou à l'action UI)
  ├─ calcule expiresAt = now + 30 000 ms
  │
  └─▶ PUBLISH QoS1  reptiles/v1/nodes/{zone}/{node-id}/cmd
        {
          "v": 1,
          "cmdId": "cmd-20241005-001",
          "correlationId": "session-abc-42",
          "target": "N-DES-04",
          "zone": "DES",
          "action": "lamp",
          "value": "off",
          "issuedAt": 1700000700000,
          "expiresAt": 1700000730000
        }

Simulateur / Node réel
  │
  ├─ reçoit la commande
  ├─ vérifie expiresAt > now → sinon ignore et ne répond pas
  ├─ traite l'action (handleCommand dans simulator.js)
  │
  └─▶ PUBLISH QoS1  reptiles/v1/nodes/{zone}/{node-id}/ack
        {
          "v": 1,
          "msgId": "…",
          "node": "N-DES-04",
          "zone": "DES",
          "ts": 1700000701000,
          "serverTs": 1700000701045,
          "seq": 210,
          "type": "ack",
          "cmdId": "cmd-20241005-001",
          "correlationId": "session-abc-42",
          "action": "lamp",
          "ok": true,
          "detail": "ok"
        }

Champs de la commande

ChampTypeDescription
vintegerVersion du format (1)
cmdIdstringIdentifiant unique de la commande — format : cmd-{YYYYMMDD}-{seq}
correlationIdstringIdentifiant de corrélation côté client (session UI, identifie qui a envoyé)
targetstringNode destinataire (ex: "N-DES-04")
zonestringZone du node
actionstringAction demandée (lamp, light, setpoint, safety_cut, interval, reboot, identify)
valuestring | number | booleanValeur associée à l'action (absent pour reboot, identify)
issuedAtinteger (ms)Horodatage d'émission
expiresAtinteger (ms)Expiration — le node ignore toute commande reçue après cette date

Comportements selon les cas d'erreur

CasComportementdetail dans ACK
Node offline Pas d'ACK. Le serveur attend jusqu'à expiresAt, puis publie une alerte de timeout sur le topic alerts. (aucun ACK)
Commande expirée (reçue après expiresAt) Le node ou le simulateur ignore silencieusement la commande. Pas d'ACK. (aucun ACK)
Action inconnue ACK ok=false "unknown_action"
Valeur invalide (setpoint hors 20-50, interval hors 5-3600) ACK ok=false "bad_value"
Action non supportée par ce type de node (ex: lamp sur un node salle) ACK ok=false "not_supported"
Relais collé (thermostat_stuck) — lamp off envoyé mais relais ne répond pas ACK ok=true mais avec avertissement "applied_but_relay_feedback_on"

Timeout et non-réponse

Le serveur démarre un timer de 30 s dès l'émission de la commande. Si aucun ACK avec le cmdId correspondant n'est reçu avant expiresAt :

  1. Le serveur marque la commande comme expirée.
  2. Il publie une alerte sur reptiles/v1/alerts/{zone}/{node-id} : 
    {
  "v": 1,
  "type": "alert",
  "level": "warning",
  "code": "cmd_timeout",
  "cmdId": "cmd-20241005-001",
  "action": "lamp",
  "message": "Aucun ACK reçu de N-DES-04 pour la commande lamp"
}
  3. Le front affiche un indicateur de commande non confirmée.

Exemple complet — commande safety_cut

Scénario : opérateur coupe le chauffage de tous les enclos DES (alerte lampe bloquée).

1. Envoi commande :

Topic : reptiles/v1/nodes/DES/N-DES-04/cmd
{
  "v": 1,
  "cmdId": "cmd-20241005-010",
  "correlationId": "incident-lamp-DES-04",
  "target": "N-DES-04",
  "zone": "DES",
  "action": "safety_cut",
  "value": true,
  "issuedAt": 1700001000000,
  "expiresAt": 1700001030000
}

2. ACK reçu :

Topic : reptiles/v1/nodes/DES/N-DES-04/ack
{
  "v": 1,
  "node": "N-DES-04",
  "zone": "DES",
  "ts": 1700001000500,
  "seq": 312,
  "type": "ack",
  "cmdId": "cmd-20241005-010",
  "correlationId": "incident-lamp-DES-04",
  "action": "safety_cut",

  "detail": "ok"
