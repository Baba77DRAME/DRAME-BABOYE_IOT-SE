Convention ClientId

Un clientId MQTT doit être unique par connexion. Une collision provoque la déconnexion du client précédent. La convention ci-dessous garantit l'unicité et permet d'identifier l'origine d'une connexion dans les logs Mosquitto.

Format général

{rôle}-{identifiant}-{suffixe-aléatoire-6-chars}

Le suffixe aléatoire (hex lowercase) évite les collisions lors des reconnexions rapides ou des instances multiples.

Conventions par rôle

RôleFormatExemples
Node réel (hardware) node-{node-id}-{6hex} node-N-DES-01-a3f2c1
node-N-EXT-02-b4d3e2
Simulateur (process unique) simulator-main-{6hex} simulator-main-c5e4f3
Front web (navigateur) front-{session-id courte}-{6hex} front-s1a2b3-d6f5a4
front-s9z8y7-e7a6b5
Administrateur / outil CLI admin-{username}-{6hex} admin-root-f8b7c6
admin-alice-a1b2c3
Service serveur (watchdog, alerting) server-{service-name}-{6hex} server-watchdog-b2c3d4
server-alerting-c3d4e5

Règles d'unicité

  • Le suffixe aléatoire 6 hex est regénéré à chaque démarrage ou reconnexion.
  • Mosquitto est configuré avec allow_duplicate_clientid false (défaut) : si deux connexions arrivent avec le même clientId, la plus ancienne est déconnectée.
  • Le simulateur n'utilise qu'un seul clientId pour l'ensemble des 28 nodes simulés — c'est l'adaptateur qui gère le démultiplexage par topic.

Identification dans les logs Mosquitto

Avec cette convention, les logs Mosquitto permettent d'identifier immédiatement le type de client :

1700000000: New connection from 192.168.1.10 on port 1883.
1700000000: New client connected from 192.168.1.10 as node-N-DES-01-a3f2c1 (p2, c1, k60, u'n-des-01').
1700000001: New client connected from 192.168.1.20 as simulator-main-c5e4f3 (p2, c1, k60, u'simulator').
1700000002: New client connected from 192.168.1.30 as front-s1a2b3-d6f5a4 (p2, c0, k30, u'frontend').
