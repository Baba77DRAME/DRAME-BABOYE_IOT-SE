Lancement et procédure de test

Prérequis

  • Docker Desktop démarré
  • Ports libres : 1883, 9001, 8080

Lancement complet

cd sujet1-iot-etudiants/support/
docker compose up --build

Lors du premier lancement, Docker construit les images. Les lancements suivants utilisent le cache :

docker compose up

En arrière-plan :

docker compose up -d --build

Ce qui se passe au démarrage

ÉtapeServiceAction
1mosquittoDémarre, charge la config, ouvre les ports 1883 et 9001
2mosquittoHealthcheck : publie un message test toutes les 5 s
3frontnginx démarre immédiatement (indépendant)
4simulator + serverDémarrent dès que mosquitto est healthy
5simulatorPublie availability online pour les 28 nodes (retain)
6simulatorDémarre la simulation — mesures toutes les 30 s / 5 min
7serverSouscrit aux topics nodes/# — surveillance des alertes active

Vérification rapide

docker compose ps

Tous les services doivent être en état running et mosquitto healthy.

Accès

InterfaceURL
Front web (dashboard)http://localhost:8080
Broker MQTT TCP (nodes réels)mqtt://localhost:1883
Broker MQTT WebSocket (navigateur)ws://localhost:9001

Logs

docker compose logs -f             # tous les services
docker compose logs -f simulator   # simulateur uniquement
docker compose logs -f server      # alertes uniquement
docker compose logs -f mosquitto   # broker uniquement

Arrêt

docker compose down          # arrête les conteneurs, conserve les volumes
docker compose down -v       # arrête ET supprime les volumes (réinitialisation complète)

Reconstruction après modification du code

docker compose up --build

Tests à effectuer

Test 1 — Dashboard en direct

  1. Ouvrir http://localhost:8080
  2. Connexion MQTT : statut connecté
  3. Simulateur : statut online
  4. Après 30 s : températures et lumières apparaissent dans les zones

Test 2 — Commande depuis le front

  1. Zone DES → N-DES-01 → bouton Lampe OFF
  2. La ligne affiche OK lamp off (ACK)

Test 3 — Alerte automatique

  1. Attendre ~2 min (scénario incidents déclenche des pannes aléatoires)
  2. Le tableau Alertes actives se remplit
  3. Les logs du serveur confirment : docker compose logs -f server

Test 4 — Résistance au redémarrage du broker

  1. docker compose restart mosquitto
  2. Simulator et server reconnectent automatiquement (backoff exponentiel)
  3. Les messages bufférisés pendant la coupure sont republié après reconnexion

Test 5 — Node réel (ESP32)

  1. Configurer l'ESP32 avec l'IP de la machine hôte, port 1883
  2. Credentials : simulator / simulator (ou créer un compte dédié)
  3. Publier sur reptiles/v1/nodes/DES/N-DES-01/telemetry
  4. Les données apparaissent dans le front web
