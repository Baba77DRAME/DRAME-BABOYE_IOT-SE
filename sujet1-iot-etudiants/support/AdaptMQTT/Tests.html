Procédure de lancement et tests

Prérequis

  • Node.js >= 20
  • Docker Desktop démarré
  • npm install exécuté dans le dossier support/

Lancement complet

Ouvrir 3 terminaux dans support/ :

TerminalCommandeRôle
1 npm run broker Démarre Mosquitto (ports 1883 et 9001)
2 npm run start:mqtt Démarre le simulateur avec l'adaptateur MQTT
3 npm run server Démarre le serveur d'alertes

Optionnel — ouvrir le front web :

npm run front

Vérification de la connexion

Le terminal du simulateur doit afficher :

[mqtt] connecté mqtt://localhost:1883 (simulator-main-xxxxxx)

Le terminal du serveur doit afficher :

[server] connecté mqtt://localhost:1883 (server-alerting-xxxxxx)

Test 1 — Réception des données

Vérifier avec mosquitto_sub (si disponible) ou depuis le front web :

mosquitto_sub -h localhost -p 1883 -u admin -P admin -t "reptiles/v1/nodes/#" -v

Attendu : messages JSON toutes les ~0,5 s (vitesse ×60) sur les topics telemetry et heartbeat.

Test 2 — Envoi d'une commande

Depuis le front web (zone DES, node N-DES-01) → bouton Lampe OFF.
Ou en ligne de commande :

mosquitto_pub -h localhost -p 1883 -u admin -P admin \
  -t "reptiles/v1/nodes/DES/N-DES-01/cmd" \
  -m '{"v":1,"cmdId":"test-001","target":"N-DES-01","action":"lamp","value":"off","expiresAt":9999999999999}'

Attendu : un message ACK sur reptiles/v1/nodes/DES/N-DES-01/ack avec ok: true et cmdId: "test-001".

Test 3 — Coupure réseau (tampon)

  1. Arrêter Mosquitto : docker compose stop mosquitto
  2. Observer le simulateur : [mqtt] connexion perdue — messages mis en tampon
  3. Attendre 30 secondes (plusieurs cycles de mesure)
  4. Relancer Mosquitto : docker compose start mosquitto
  5. Observer la vidange : [mqtt] vidange tampon : N message(s) en attente
  6. Vérifier que les événements porte bufférisés arrivent bien dans le serveur d'alertes

Test 4 — Backoff exponentiel

  1. Arrêter Mosquitto
  2. Observer les tentatives de reconnexion dans la console du simulateur :
[mqtt] connexion perdue — messages mis en tampon
[mqtt] reconnexion dans 3.0 s (backoff x2, max 30 s)...
[mqtt] tentative de reconnexion...
[mqtt] reconnexion dans 6.0 s (backoff x2, max 30 s)...
[mqtt] tentative de reconnexion...
[mqtt] reconnexion dans 12.0 s (backoff x2, max 30 s)...
...
[mqtt] reconnexion dans 30.0 s (backoff x2, max 30 s)...  ← plateau

Test 5 — Variables d'environnement

MQTT_BUFFER_MAX=10 MQTT_RECONNECT_MIN_DELAY=1000 \
  node src/index.js --output mqtt

Avec un tampon de 10 messages, un avertissement doit apparaître rapidement si le broker est arrêté.

Test 6 — Alerte automatique

Le scénario incidents (défaut) provoque des pannes aléatoires. Attendre ~2–5 minutes (simulées) pour voir :

  • Une alerte probe_disconnected (sonde DS18B20 retourne −127 °C)
  • Une alerte door_open_timeout (porte restée ouverte > 15 min simulées)
  • Une alerte battery_low (nodes EXT ou DOOR)

Les alertes apparaissent dans le terminal du serveur et dans le front web.

Vérification simulator.js / scenarios.js inchangés

git diff HEAD -- src/simulator.js src/scenarios.js

Attendu : aucune sortie (aucune modification).
